# 公民 / 废墟 / 开发者模式设计（2026-11-10）

> 需求来源：根目录 `新计划.txt`
> 本轮只做设计，不改代码。实现前先把验收标准写入 `backlog.json`。
> 关键决策已与用户确认：
> 1. 公民修好塔后按状态机字面执行：立刻“进驻 → 销毁”（公民被消耗）。
> 2. 感知范围内同时有废墟和已建成建筑时：**废墟优先**。
> 3. 开发者模式用 **F2 热键 + Inspector 初始开关**。
> 4. 检测范围球覆盖**所有单位**；箭塔显示攻击范围。

## 1. 目标与范围

### 1.1 本轮目标

1. **开发者模式**：可开关地显示所有单位的检测范围，用半透明球体表示。
2. **新单位：公民**（Citizen）：按给定状态机自主修建废墟、进驻建筑或攻击敌人。
3. **新建筑：废墟**（Ruined Tower）：可被公民修复为箭塔，建造条 500，被打断保留进度，废弃状态不能被敌人攻击。
4. **测试场景改造**：`RoadWorkflow_Test` 里现有的两个塔位变为废弃塔，每个塔位旁生成一个公民，5 秒修好；其他布置不变。

### 1.2 不做的事

- 不引入通用建造系统/资源消耗/玩家操作 UI。
- 不做多选建筑、建筑升级树、公民生产队列。
- 不改 `MVP.unity`（保留用户未提交的 `groundMask.m_Bits = 51` 修改）。
- 不接 CI；验证仍在本地编辑器内完成。

## 2. 现状核对（实现前的事实）

| 现状 | 结论 |
|---|---|
| `UnitDefinition` 只有血量/攻击/移速/攻击间隔/射程/溅射，没有感知范围、生产力 | 需要扩展 |
| `StatBlock.StatType` 只有 6 个属性 | 需要新增 `PerceptionRange`、`Productivity` |
| 敌人/战士的感知范围是各自 Brain 上的私有序列化字段（`acquireRange=7`、`detectRange=10`） | 保留为回退值，新增统一的 `IPerceptionSource` 供可视化读取 |
| `UnitRegistry` 只登记 `UnitHealth`；死亡/禁用即注销 | “废弃不能被敌人打”可直接通过**禁用 `UnitHealth`** 实现 |
| `UnitHealth` 的 `destroyOnDeath`、`Died` 事件、`HealthBar` 已成熟 | 公民死亡复用该链路 |
| `UnitTurretBrain` 原地索敌；`Unit.abilitiesEnabled` 是塔的攻击总开关 | 废墟阶段关闭，修好后打开 |
| `UnitMotor`（NavMesh）与 `UnitMover`（贴地路点）通过 `UnitLocomotion` 抽象 | 公民用 `NavMeshAgent + UnitMotor`，与战士一致 |
| `RoadWorkflow_Test` 当前是 4 战士 + 2 座**攻击箭塔** + 30 敌人 + 巡逻点 | 新场景把 2 塔替换为 2 废墟 + 2 公民，其余保留 |
| 编辑器一键布置在 `UnitDemoSetup`（`UnitAITestSetup` / `UnitProjectileTestSetup` 是 partial 菜单） | 新增一个菜单复用 `BuildAITestScene`，避免手改场景 YAML |
| 输入设置 `activeInputHandler: 2`（Both） | `Input.GetKeyDown` 可用；代码仍加条件编译保护 |

## 3. 数据模型改动

### 3.1 `UnitDefinition`

新增两个策划字段（默认 0，保持旧资产行为不变）：

```csharp
[Header("感知与生产")]
[Min(0f)] public float perceptionRange = 0f; // 感知范围（米）
[Min(0f)] public float productivity = 0f;    // 生产力（建造点/秒）
```

### 3.2 `StatType`

```csharp
public enum StatType
{
    MaxHealth,
    Attack,
    MoveSpeed,
    AttackInterval,
    Range,
    SplashRadius,
    PerceptionRange, // 新增
    Productivity     // 新增
}
```

`Unit.Awake` 同步写入两个基础值。

### 3.3 数值表

| 单位 | 队伍 | 血量 | 攻击 | 移速 | 攻击间隔 | 攻击范围 | 感知范围 | 生产力 |
|---|---|---|---|---|---|---|---|---|
| 公民 Citizen | Player | 30 | 2 | 2 | 2 | 1.5 | 2 | 100 |
| 普通敌人 Enemy | Enemy | 100 | 10 | 2 | 2 | 1.5 | 7 | 0 |
| 战士 Warrior | Player | 50 | 5 | 4 | 2 | 2 | 10 | 0 |
| 箭塔 Tower | Player | 500 | 5 | 0 | 1 | 20 | —（用攻击范围） | 0 |

- 敌人/战士的 `perceptionRange` 与现有 Brain 字段一致，保证不回归。
- 箭塔不配置感知范围，开发者模式直接显示 `Unit.GetAttackRange()`。

## 4. 建筑系统

### 4.1 `UnitBuilding`（新组件）

挂载在塔/废墟根物体上，是“废墟/已建成”的唯一权威状态。

```csharp
public enum BuildingStatus
{
    Ruined,      // 废墟：可修建、不可被攻击
    Operational  // 已建成：正常箭塔
}

[DisallowMultipleComponent]
public class UnitBuilding : MonoBehaviour
{
    [SerializeField] private UnitTeam team = UnitTeam.Player;
    [SerializeField] private BuildingStatus initialStatus = BuildingStatus.Ruined;
    [SerializeField, Min(1f)] private float buildRequired = 500f;
    [SerializeField, Min(0.1f)] private float interactRange = 1.5f;
    [SerializeField] private Material ruinedMaterial;
    [SerializeField] private Material operationalMaterial;
    [SerializeField] private UnitHealth health;
    [SerializeField] private Unit unit;
    [SerializeField] private UnitTurretBrain turret;
    [SerializeField] private HealthBar healthBar;
    [SerializeField] private BuildProgressBar buildBar;
    [SerializeField] private Renderer targetRenderer;
    [SerializeField] private bool logChanges = true;

    public BuildingStatus Status { get; }
    public bool IsRuined => Status == BuildingStatus.Ruined;
    public bool IsOperational => Status == BuildingStatus.Operational;
    public UnitTeam Team => team;
    public float BuildRequired => buildRequired;
    public float BuildProgress { get; }      // 运行时状态，持久保存在实例上
    public float Progress01 { get; }         // 0..1
    public float InteractRange => interactRange;

    public event Action<UnitBuilding> ProgressChanged;
    public event Action<UnitBuilding> Completed;
    public event Action<UnitBuilding, Unit> Garrisoned;

    public bool CanBeWorkedBy(Unit worker);  // 同队 + Ruined + 工人存活
    public bool AddBuildProgress(float amount); // 返回是否本次完成
    public bool Garrison(Unit occupant);    // 仅 Operational；销毁公民
}
```

#### 生命周期

| 阶段 | Ruined | Operational |
|---|---|---|
| `UnitHealth` | **禁用** → 不进 `UnitRegistry`，敌人/溅射/拦截都找不到 | 启用 → 可被攻击 |
| `Unit.abilitiesEnabled` | `false`，不攻击 | `true` |
| `UnitTurretBrain` | 禁用 | 启用 |
| 血条 `HealthBar` | 隐藏 | 显示 |
| 建造条 `BuildProgressBar` | 显示（0..1） | 隐藏 |
| 外观 | 灰色 `ruinedMaterial` | 蓝色 `operationalMaterial` |
| 移动 | 不移动（塔本身 `canMove=false`） | 不移动 |

- 进度存在 `UnitBuilding` 实例上（`BuildProgress`），**不是 ScriptableObject**，符合“运行时状态不放 SO”的不变量。
- 被打断（公民死亡、离开、目标失效）时没有 ticker，`BuildProgress` 自然保留；再次有公民修建时从原值继续。
- `Complete()`：状态切 Operational → 启用 `UnitHealth`（触发 `OnEnable` 注册进 `UnitRegistry`）→ 打开能力与炮台 AI → 换材质 → 隐藏建造条、显示血条 → 触发 `Completed`。
- `Garrison(occupant)`：仅 Operational 且同队；记录事件后 `Destroy(occupant.gameObject)`。公民“销毁”不走 `UnitHealth.TakeDamage`，避免触发死亡/掉落等后续逻辑。

#### 关键实现注意

1. **组件顺序**：预制体里按 `UnitHealth → Unit → AttackAbility → UnitTurretBrain → UnitBuilding → HealthBar → BuildProgressBar` 排列，保证 `Unit.Awake` 先于 `UnitBuilding.Awake`。
2. **初始状态在 `Start` 应用**：`HealthBar`/`BuildProgressBar` 都在各自 `Awake` 里创建对象，`UnitBuilding.Start` 再统一设置显隐，避免 Awake 顺序导致的“残影血条”。
3. **禁用 `UnitHealth` 不会阻止 `Awake`**：Unity 仍会调用被禁用组件的 `Awake`，`Unit.Awake` 里的 `health.Initialize(500, Player)` 正常执行；启用时 `OnEnable` 再注册。
4. **废墟碰撞体保留**：敌人靠 `UnitRegistry` 索敌，不靠物理射线；保留碰撞体不影响“不能被打”，但方便后续点击/寻路避让。

### 4.2 `UnitBuildingRegistry`（新静态注册表）

```csharp
public static class UnitBuildingRegistry
{
    public static IReadOnlyList<UnitBuilding> All { get; }
    public static void Register(UnitBuilding building);
    public static void Unregister(UnitBuilding building);

    // preferRuined=true：先找最近废墟；找不到再找最近已建成建筑。
    public static UnitBuilding FindNearestFriendly(
        Vector3 position, UnitTeam team, float maxDistance, bool preferRuined);
}
```

- `UnitBuilding.OnEnable/OnDisable` 成对注册/注销。
- 只返回**同队**且未被销毁的建筑；中立建筑不参与。
- 废墟优先的实现：两轮扫描（第一轮只接受 `IsRuined`，第二轮接受任意状态），而不是先取最近再判断。

### 4.3 `BuildProgressBar`（新组件）

- 世界空间双 Quad（背景 + 黄色填充），实现方式复用 `HealthBar` 的思路：
  - 独立 GameObject，不挂在单位子层级，**无 Collider**，`Ignore Raycast` 层；
  - `LateUpdate` 跟随 `UnitBuilding.transform.position + up * heightOffset`，billboard 朝向主相机；
  - 订阅 `UnitBuilding.ProgressChanged`，按 `Progress01` 缩放填充；
  - `SetVisible(bool)` 由 `UnitBuilding` 控制。
- 默认高度 `heightOffset = 2.6`，宽度 1.4。

### 4.4 `HealthBar` 小改

把现有私有 `SetVisible(bool)` 提升为 `public`，供 `UnitBuilding` 在废墟阶段隐藏、建成后显示。其余逻辑不动。

## 5. 公民（Citizen）

### 5.1 资产

- `Assets/UnitData/Citizen.asset`：按 3.3 数值表配置。
- `Assets/Prefabs/Unit/Citizen.prefab`：
  - Capsule（比战士略小，例如 scale `0.7, 0.9, 0.7`），黄/橙色材质；
  - `UnitHealth`、`Unit`、`AttackAbility`、`NavMeshAgent` + `UnitMotor`、`CitizenBrain`、`HealthBar`；
  - 与 `Warrior_Guard.prefab` 相同的 Agent 配置（radius 0.4 / height 2 / baseOffset 1 / angularSpeed 540）。
- 公民攻击为直接伤害（不配 `projectilePrefab`），与战士一致。

### 5.2 状态机

```
Idle
 ├─ 感知范围内是否有建筑？
 │   ├─ 是（优先最近的废墟）
 │   │   ├─ 是废墟 → MoveToRepair → 到达交互距离 → Repair（按生产力推进建造条）
 │   │   └─ 否     → MoveToGarrison → 到达 → Garrison → 销毁自己
 │   └─ 否 → 感知范围内是否有敌人？
 │           ├─ 是 → Chase → 进入攻击范围 → Attack
 │           └─ 否 → Idle（原地停止）
攻击目标丢失 → Idle（下一轮重新扫描）
任何状态 + 生命值归零 → 死亡（禁用 Brain、停止移动）
```

补充规则（按本轮确认）：

1. **建筑优先于敌人**：只要感知范围内有可处理建筑，公民不索敌。该判定发生在 Idle / 目标丢失后的重新扫描；已经进入 Attack 的公民要等目标丢失才重新扫描。
2. **废墟优先**：`UnitBuildingRegistry.FindNearestFriendly(..., preferRuined: true)`。
3. **修好即进驻**：`Repair` 中建筑完成 → 下一帧看到 `IsOperational` → `MoveToGarrison` → 到达后 `Garrison` 销毁公民（严格按需求文字）。
4. **修建中被攻击不还手**：建筑优先，公民继续修建；生命归零则死亡，建造条保留。
5. **建造条保留**：进度在建筑实例上，与公民生命周期无关。

### 5.3 `CitizenBrain`（新组件）

```csharp
public enum CitizenState
{
    Idle,
    MoveToRepair,
    Repair,
    MoveToGarrison,
    Chase,
    Attack
}

[DisallowMultipleComponent]
[RequireComponent(typeof(Unit))]
public class CitizenBrain : MonoBehaviour, IPerceptionSource
{
    [SerializeField, Min(0f)] private float perceptionRange = 2f; // 回退值，优先读 StatBlock
    [SerializeField, Min(0.05f)] private float searchInterval = 0.25f;
    [SerializeField] private bool logState = true;

    public CitizenState State { get; }
    public string StateName { get; }        // 测试断言
    public UnitBuilding BuildingTarget { get; }
    public IDamageable Target { get; }
    public float PerceptionRange { get; }   // StatBlock > 0 ? stat : perceptionRange
}
```

`Update()` 主流程：

1. 自身不存活 / 无 `UnitLocomotion` → return。
2. **有建筑目标**：
   - 目标被销毁/不同队 → 清空，回 Idle；
   - `IsOperational` → `MoveToGarrison`；到达 `InteractRange` 内 → `Garrison(unit)` 并 return；
   - `IsRuined` → 超出 `InteractRange` 则 `MoveToRepair` 并向建筑移动；在范围内则 `Repair`：`Halt()` + `AddBuildProgress(productivity * deltaTime)`。
   - 建筑分支结束直接 return，不索敌。
3. **有敌人目标**：射程内 → `Attack`（`Halt()` + `unit.ActivateAbilities(target)`）；否则 `Chase`（`MoveTo`）。
4. **无目标**：按 `searchInterval` 扫描：
   - `UnitBuildingRegistry.FindNearestFriendly(pos, team, PerceptionRange, preferRuined: true)`；
   - 没有建筑 → `UnitRegistry.FindNearestHostile(pos, team, PerceptionRange)`；
   - 都没有 → `Idle` + `Halt()`。
5. 缓存的 `IDamageable` 必须做 Unity 假空判断（`target as Object == null`）后再读 `IsAlive`，与现有 Brain 一致。
6. `OnEnable/OnDisable` 订阅/注销 `UnitHealth.Died`；死亡时 `enabled=false`、清空目标、`locomotion.Halt()`。

生产力读取：`unit.Stats.Get(StatType.Productivity)`，500 / 100 = **5 秒**。

### 5.4 `IPerceptionSource`（新接口）

```csharp
public interface IPerceptionSource
{
    float PerceptionRange { get; } // <=0 表示当前不显示
}
```

实现：

| 组件 | `PerceptionRange` |
|---|---|
| `EnemyBrain` | `StatBlock.PerceptionRange > 0 ? stat : acquireRange` |
| `WarriorBrain` | `StatBlock.PerceptionRange > 0 ? stat : detectRange` |
| `CitizenBrain` | `StatBlock.PerceptionRange > 0 ? stat : perceptionRange` |
| `UnitTurretBrain` | `isActiveAndEnabled ? unit.GetAttackRange() : 0` |

- 保留原有序列化字段作为回退，避免旧预制体/测试桩不配置 Definition 时行为变化。
- `AcquireTarget` 改为使用 `PerceptionRange`；数值与旧字段一致，不回归。

## 6. 开发者模式

### 6.1 开关

- `DeveloperMode` 静态类：

```csharp
public static class DeveloperMode
{
    public static bool Enabled { get; }
    public static event Action<bool> Changed;
    public static void SetEnabled(bool value);
}
```

- `DeveloperModeController`（MonoBehaviour，运行时自动创建）：
  - `[SerializeField] private bool startEnabled = false;`
  - `[SerializeField] private KeyCode toggleKey = KeyCode.F2;`
  - `[SerializeField, Range(0.02f, 0.3f)] private float sphereAlpha = 0.12f;`
  - `Update()`：`Input.GetKeyDown(toggleKey)` → 切换；日志输出当前状态。
  - `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]` 自动创建 `[DeveloperMode]` 对象（`DontDestroyOnLoad`）；若场景里已有则不重复创建。
  - 使用 `#if ENABLE_LEGACY_INPUT_MANAGER` 包裹热键；否则只保留 Inspector/静态开关并输出一次提示（当前项目是 Both，热键可用）。

### 6.2 球体显示

`DeveloperModeController` 在 `LateUpdate` 同步：

1. 遍历 `UnitRegistry.All` 中存活的 `UnitHealth`；
2. 取同物体上的 `Unit` 与 `IPerceptionSource`；
3. `PerceptionRange <= 0`（如废墟的炮台被禁用）→ 跳过；
4. 为每个单位维护一个球体 GameObject（`Dictionary<UnitHealth, GameObject>`）：
   - 共享一份单位球 Mesh（半径 0.5）与按队伍缓存的材质；
   - `position = health.DamageTransform.position + Vector3.up * 0.5f`；
   - `scale = Vector3.one * (PerceptionRange * 2f)`（Unity 内置球直径 1）；
   - **无 Collider**，`Ignore Raycast` 层，关闭阴影与接收阴影；
   - 队伍颜色：Player 绿、Enemy 红、Neutral 灰，alpha 使用 `sphereAlpha`。
5. 关闭开发者模式、单位死亡/销毁时销毁对应球体并清理字典；`OnDestroy` 清理全部。

### 6.3 材质

运行时创建透明材质：

- 首选 `Universal Render Pipeline/Unlit`：设置 `_BaseColor`（alpha）、`_Surface=1`、`_SrcBlend=SrcAlpha`、`_DstBlend=OneMinusSrcAlpha`、`_ZWrite=0`、`_Cull=0`，启用 `_SURFACE_TYPE_TRANSPARENT`，`renderQueue = 3000`；
- 找不到 URP Unlit 时回退 `Sprites/Default`，再回退 `Unlit/Color`（与 `HealthBar` 的降级链一致）。
- 材质 `HideFlags.DontSave`，每个队伍材质只创建一次。

### 6.4 不干扰玩法

- 球体不挂 `UnitHealth`、不参与 `UnitRegistry`、无 Collider；
- 放在 `Ignore Raycast` 层，`UnitMover.groundMask` 已排除该层（`m_Bits=51`），不会影响贴地探测；
- 仅在开发者模式开启时创建，关闭即销毁，避免常驻开销。

### 7.3 预期表现

1. PlayMode 开始后，两个公民在 2m 感知范围内发现废墟，进入 `Repair`；
2. 生产力 100，建造条 500 → **连续工作 5 秒**后两座塔变为 Operational，开始用投射物攻击敌人；
3. 修好后公民按确认的行为进驻并销毁（场景中不再有公民）；
4. 若公民在 5 秒内被敌人击杀，建造条停在当前进度，不会清零；
5. 废墟阶段敌人无法选中/攻击它；建成后恢复为普通可攻击箭塔；

### 感知球重叠变深修复（2026-11-15）

- **现象**：开发者模式（F2）下多个单位的半透明感知球重叠后颜色逐层累加，几十个敌人挤在一起时画面变成一片实色，看不见场景与单位。
- **原因**：球体用普通透明混合（`SrcAlpha OneMinusSrcAlpha`、`ZWrite Off`），N 层重叠后该像素 alpha = 1 − (1 − 0.18)^N；30 个敌人彼此距离 < 6m 时有 300+ 对球体重叠，10 层就到 86% 不透明度。
- **修复**：
  - 新增 `Assets/Resources/Shaders/PerceptionVolume.shader`（`Vindicator/PerceptionVolume`）：在同一 Pass 内用模板缓冲做到“同一像素只保留最先画到的那个球”——第一个球写入 `Ref 1`，后续球 `Comp NotEqual` 直接丢弃，**重叠不再累加**。注意透明队列按“远 → 近”绘制，所以留在像素上的通常是**较远**的那个球；同阵营球颜色相同，只有不同阵营重叠时才会看到较远一方的颜色。
  - 填充降到 `_BaseColor.a = 0.10`，另加 Fresnel 边缘（`_RimColor` alpha 0.55、`_RimPower` 2.5）提亮轮廓，所以单层也很容易看出来。
  - `DeveloperModeController` 把 `sphereAlpha` 默认值 0.18 → 0.10，新增 `rimAlpha` / `rimPower` 序列化字段；材质创建优先用专用 shader，找不到时退回原 `Universal Render Pipeline/Unlit` 半透明路径（旧行为）。材质仍按阵营各一份共享，不随单位数量增长。
  - shader 放在 `Resources/` 下，保证打包时不会被剥离（运行期靠 `Shader.Find` 加载）。
- **代价（已知）**：被模板丢弃后，重叠区域里只有“最先画到”的那个球的边缘条纹可见，内部不会出现每个球的完整轮廓；这是用统一透明度换取可读性的取舍。
- **验证**：`RoadWorkflow_Test` PlayMode 中 33 个球、315 对 6m 内重叠，截图 `Assets/Screenshots/perception-volume-after-20261115.png`（新）对比 `Assets/Screenshots/perception-volume-before-20261115.png`（临时换回旧材质），新旧对照下建筑与单位在新材质中始终清晰可辨；33 个球全部使用 `Vindicator/PerceptionVolume`。
