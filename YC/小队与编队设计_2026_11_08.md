> 文档日期沿用计划日期 11.8，实现与验证记录写在文末（2026-11-15）。

## 1. 范围

本计划在现有 NavMesh 单位系统上补齐四件事：

1. **站位与移动算法**：多个同阵营单位按队形占据槽位并按槽位移动。
2. **群体行为（AI 行为树）**：以小队为单位做“待命 → 编队移动 → 集火攻击”的决策。
3. **玩家操作**：框选友军、右键移动/攻击、编队面板（组建与显示）。
4. **开发者数据**：全局“小队 / 单位”两张表，并取消拦截、调整民兵感知、为每个单位增加追逐/锁定指针。

不在本轮范围：玩家编队的存档、跨场景保留、寻路避障的专用算法（仍由 NavMeshAgent 负责）、PlayMode 自动验收。

## 2. 术语与优先级

| 术语 | 含义 |
|---|---|
| 小队 Squad | 玩家显式组建（框选后按 `G` 或 `Ctrl+数字`）的一组同阵营可指挥单位；每个单位最多属于一个小队。选择与移动/攻击命令都不会自动建队。 |
| 编队 Formation | 小队的目标队形与每个成员的槽位；支持横队 `Line`、纵队 `Column`、方阵 `Grid`。 |
| 小队命令 Order | 玩家对小队下达的 `Move` / `Attack`。命令优先级高于个体 AI。 |
| 追逐单位 ChaseTarget | 该单位正在尝试**靠近**的目标（`Transform`）。 |
| 锁定单位 LockTarget | 该单位正在尝试**攻击**的目标（`Transform`）。 |

语义约定：

- 追击时只写 `ChaseTarget`，攻击时只写 `LockTarget`；两者互斥，单位待命/巡逻时都为空。
- 玩家命令存在期间，`WarriorBrain` 先执行命令，命令结束后才恢复个体 AI。
- 目标死亡、对象销毁或指令完成时，指针与命令必须清空，避免悬空引用。

## 3. 数据模型

### 3.1 小队表（开发者模式第一张表）

| 字段 | 说明 |
|---|---|
| `squad_id` | 从 1 递增，运行期唯一。 |
| `name` | 显示名，默认“小队 N”。 |
| `team` | 阵营，玩家编队固定 `Player`。 |
| `formation` | 当前队形（Line / Column / Grid）。 |
| `member_count` | 存活成员数。 |
| `anchor` / `facing` | 编队锚点与朝向。 |
| `state` | `Idle` / `Moving` / `Engaging`，由群体行为树输出。 |
| `target` | 当前集火目标名称（没有则为 `-`）。 |

### 3.2 单位表（开发者模式第二张表）

| 字段 | 说明 |
|---|---|
| `name` / `team` | 单位名与阵营。 |
| `state` | 该单位 Brain 的状态名（Idle / Chase / Attack / Patrol / Return / …）。 |
| `chase_target` | 追逐单位名（没有则为 `-`）。 |
| `lock_target` | 锁定单位名（没有则为 `-`）。 |
| `squad_id` | 所属小队编号（没有则为 `-`）。 |

两张表都由注册表实时生成，不做持久化；每帧刷新，对象销毁时显示 `-`。

## 4. 编队站位与移动

### 4.1 槽位公式

给定锚点 `anchor`、朝向单位向量 `forward`（水平面）、成员数 `n`、间距 `spacing`：

```
right = normalize(cross(up, forward))
columns = Line → n；Column → 1；Grid → ceil(sqrt(n))
rows    = ceil(n / columns)
slot(i): col = i % columns, row = i / columns
  lateral = (col - (columns - 1) / 2) * spacing
  depth   = ((rows - 1) / 2 - row) * spacing
  pos     = anchor + right * lateral + forward * depth
```

- 所有槽位相对锚点对称，第一排在朝向前方。
- 相邻槽位间距等于 `spacing`，同列行距也等于 `spacing`。
- 下发给单位前先做 `NavMesh.SamplePosition`（半径 = 2 × spacing），失败则使用原槽位；测试中可关闭吸附。

### 4.2 移动语义

1. 小队收到 `MoveTo(anchor, facing)` 后为每个存活成员计算槽位。
2. 通过 `UnitCommander.IssueMove(slot, squadId)` 写入移动命令。
3. `WarriorBrain.Update` 检测到命令后：`ChaseTarget` 清空、`Locomotion.MoveTo(slot)`，到达 `arriveRadius` 后清空命令。
4. 小队在全部成员到达后把状态从 `Moving` 切回 `Idle`。
5. 成员死亡/离开时从小队移除并重排剩余成员的槽位。

## 5. 群体行为树

实现 `Assets/Script/Unit/AI/` 下最小行为树框架（`Sequence` / `Selector` / `Condition` / `Action`），`SquadBrain` 每秒/每帧 Tick：

```
Selector
├─ Sequence  攻击命令有效
│  ├─ Condition 小队有存活集火目标
│  └─ Action    维持攻击（成员各自进入射程攻击）
├─ Sequence  移动命令有效
│  ├─ Condition 仍有成员未到槽位
│  └─ Action    维持编队移动
├─ Sequence  无命令且发现敌人
│  ├─ Condition 小队感知范围内存在敌对单位，且未处于 ManualControl
│  └─ Action    对最近敌人下达攻击命令
└─ Action    待命（清空过期命令，保持队形）
```

- 小队感知范围取成员 `IPerceptionSource.PerceptionRange` 的最大值，以小队质心为中心。
- `Squad.ManualControl`：玩家给部分成员下过个体命令后置位，自动接敌分支跳过；`Squad.MoveTo` / `Squad.Attack` 等小队级命令解除（见 §12.8）。
- 行为树只负责**发布/撤销命令**，具体移动与攻击仍由单位 Brain + `AttackAbility` 执行，便于 EditMode 测试。
- 状态输出：`Idle` / `Moving` / `Engaging`，供面板与开发者表读取。

## 6. 玩家操作

| 操作 | 行为 |
|---|---|
| 左键拖拽 | 框选 `Player` 阵营的可指挥单位（`WarriorBrain`）。 |
| Shift + 框选 | 追加选择。 |
| 左键点击空地 | 清空选择。 |
| 右键点地面（未编队） | 选中单位各自移动，**保持相对位置**；不创建小队。 |
| 右键点地面（整队选中） | 该小队按当前队形（Grid）移动到点击点。 |
| 右键点敌人（未编队） | 选中单位各自攻击该目标；不创建小队。 |
| 右键点敌人（整队选中） | 该小队集火该目标。 |
| `G` | 把当前选择编成一个新小队，**编号由注册表自增**（1、2、3…）。 |
| `1`–`9` | 选择对应编号的小队（没有则忽略）。 |
| `Ctrl + 1`–`9` | 把当前选择编为**指定编号**的小队（覆盖同编号旧队）。 |
| 面板「组建编队」 | 等同 `G`：新小队、编号自增。 |
| 面板「解散」 | 解散该小队，成员恢复个体 AI。 |

**默认不编队**：选择、移动、攻击都不会自动产生小队；小队只由 `G` / `Ctrl+数字` / 面板按钮显式创建。

只有当前选择**恰好覆盖某个小队的全部存活成员**时才走编队逻辑（`PlayerCommandController.SelectionSquad()`）；混编、跨队、只选中部分成员都按个体命令处理，并让这些单位所属小队放弃旧的编队命令，避免小队行为树把槽位重新盖回来。

选择框与面板均为运行期创建，不写进场景资产；场景只需保留现有的 4 名战士即可验收。

## 7. 开发者模式

- `F2`：沿用现有感知球开关。
- `F3`：显示/隐藏两张数据表（仅在开发者模式开启时生效）。
- 两张表使用 IMGUI 绘制，左上角半透明面板；不依赖 Canvas/字体资产，PlayMode 与 EditMode 均可读取同一份 `DeveloperTableData`。
- 表内所有引用先做 Unity 对象有效性判断，销毁单位不会让表格报错。

## 8. 取消拦截与民兵感知

1. **拦截暂时关闭**：`WarriorBrain.interceptEnabled` 与 `EnemyBrain.interceptEnabled` 默认 `false`。
   - 关闭时战士只按感知范围锁定目标并追击，不再发 `InterceptRequested`；
   - 敌人不再接受/维持拦截关系，按普通“感知 → 追击 → 攻击”运行；
   - 旧拦截逻辑保留在代码中，Inspector 打开开关即可恢复，原有拦截测试在显式开启开关后继续通过。
2. **民兵检测 10 → 4**：`Warrior_Guard` 模板 `perceptionRange = 4`，`WarriorBrain.detectRange` 默认 4，场景预制体同步为 4。
   - 影响：民兵只在 4m 内主动接敌，符合“士兵是宝贵资源、不应被轻易拉入战斗”的设计意图。
   - 拴绳仍为 14m，追击不会无限扩张。

## 9. 状态机调整

敌人/友军状态机改为显式的“目标指针”模型：`Idle → Chase → Attack → (Patrol/Return)`。
完整可读版本见 [单位状态机_2026_11_08.md](单位状态机_2026_11_08.md)。核心变化：

- 移除拦截对应的分支；
- 追击时维护 `ChaseTarget`，攻击时维护 `LockTarget`；
- 玩家命令优先于个体 AI；
- 公民同样维护两个指针（修建途中不写锁定的例外见状态机文档）。

## 10. 验收标准

对应 `.agent/tasks/backlog.json` 的 `squad-*` / `player-rts-*` / `unit-target-pointers` / `intercept-militia-perception` / `developer-squad-tables` / `squad-state-machine-doc` 任务：

1. `FormationLayout` 对 Line/Column/Grid 生成恰好 N 个槽位，间距 = `spacing`，相对锚点对称，随朝向旋转。
2. `Squad` 能把 N 个单位编组，为每个成员下发唯一槽位移动命令；解散后命令与小队编号清空。
3. 群体行为树在无敌人时输出 Idle、有移动命令时输出 Moving、发现敌人时输出 Engaging 并下达攻击命令；目标死亡后回到 Idle。
4. 框选只选中 Player 阵营可指挥单位；右键移动/攻击分别写入 `Move`/`Attack` 命令；单位到达或目标死亡后命令自动清空。
5. 编队面板列出所有小队、成员数与状态，支持组建/选择/解散。
6. 每个敌人/友军/公民都能输出 `ChaseTarget` / `LockTarget`：追击时只有追逐指针，攻击时只有锁定指针，待命/死亡时都为空。
7. `Warrior_Guard` 感知 = 4；默认关闭拦截时战士不发拦截请求、敌人忽略拦截请求；显式开启后旧拦截测试仍通过。
8. 开发者模式 F3 显示两张表，包含上述字段，销毁对象后不抛异常。
9. Unity 编译 0 error / 0 warning；全部 EditMode 测试通过。

## 11. 测试与已知限制

- 自动化只覆盖 EditMode：站位纯函数、小队命令、行为树状态、目标指针、面板数据行、感知数值、拦截开关。
- 选择框、右键射线、uGUI 面板、F3 表格的**视觉表现**已做一次 PlayMode 冒烟（见 §12.4）；鼠标输入手感仍建议人工确认。

### 12.5 框选问题排查与改进（2026-11-15 下午）

用户反馈“目前框选不了”。逐项排查结果：

- **输入链路正常**：`PlayerCommandController.Update` 的 IL 确实调用框选处理；`Input.mousePosition` 在运行时可读（证明旧输入后端启用）；`EventSystem` 只有一个 `StandaloneInputModule`；场景只有一个 `MainCamera`；`MainCamera` 下 4 名战士屏幕坐标均完整落在视口内；全屏矩形 `UnitsInScreenRect` 返回 4。
- **找到两个体验层原因**：
  1. **没有任何可视反馈**：拖拽时没有选择框，选中后没有标记，玩家无法判断输入是否生效。
  2. **验收场景友军存活时间很短**：`AI_Spawner` 0.5s 后每秒刷 1 个敌人、共 30 个；实测 4 名 50HP 民兵在 **约 52 秒内只剩 1 名**。若此时再框选，场上已没有可指挥单位。
- **改进**：
  - 拖拽时绘制半透明选择框与亮色边框；选中的单位头顶画绿色小方框。
  - 框选判定改用 `Renderer.bounds` 的屏幕投影（覆盖身体而不只是脚底枢轴），无 Renderer 时回退到枢轴 ±8px。
  - 增加 **F1 全选** 存活可指挥单位。
  - 拖拽开始/结束在 Console 打印 `[Select]` 日志（`logSelection` 开关，默认开），用于确认输入是否到达。
  - 面板标题改为“已选 N 人 / 可指挥 M 人”，可指挥为 0 时能直接看出是士兵已阵亡而非输入失效。
- **验证**：API 全选 4 人成功；每个战士 30×30px 小框都能单独选中；截图 `Assets/Screenshots/selection-markers-20261115.png` 中 4 个绿色标记与面板计数均正常；EditMode 97/97（新增 `UnitsInScreenRect_UsesRendererBoundsNotOnlyPivot`、`SelectAllPlayerWarriors_PicksOnlyCommandableWarriors`）。
- **建议测试方式**：进入 Play 后先点击一次 Game 视图使其获得焦点，再框选；若 1 分钟后士兵已阵亡，可在 Hierarchy 中临时禁用 `AI_Spawner` 再测试编队操作。

### 12.7 编队改为手动 + 自增编号（2026-11-15 傍晚）

- **问题**：`IssueMoveCommand` / `IssueAttackCommand` 原先调用 `EnsureSelectionSquad()`，右键移动或攻击会在后台悄悄建一个小队 —— 玩家想"只选了个路过"也会留下编队，面板行数越点越多。
- **改法**：
  - 新增 `PlayerCommandController.SelectionSquad()`：**只读**判断当前选择是否恰好覆盖某个小队的全部存活成员，不创建任何东西。
  - 移动 / 攻击只在整队被选中时走 `Squad.MoveTo` / `Squad.Attack`；否则对每个选中单位下个体命令：移动用**质心相对偏移**（保持当前站位），攻击直接 `UnitCommander.IssueAttack`。
  - 下个体命令前调用 `DropSquadOrders()`：让这些单位所属小队 `CompleteOrders()`，防止小队行为树把旧槽位重新下发。
  - 删除 `EnsureSelectionSquad()`；新增 `CreateSquadFromSelection()`（0 参 = 自动编号，1 参 = 指定编号），`AssignSquad(id)` 改为薄封装。
