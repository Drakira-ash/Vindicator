## 二、运行时结构

```
Unit（根，RequireComponent UnitHealth）
├─ UnitHealth          IDamageable：血量、受伤/死亡事件、注册进 UnitRegistry
├─ StatBlock           运行时属性容器（SetBase / Get / 修饰值）
├─ UnitAbility[]       AttackAbility 等能力组件，由 Unit 统一调度
├─ UnitMover           沿 UnitRoute 的贴地移动
├─ EnemyBrain          敌人 AI（发现→停下攻击→目标死亡后继续走）
└─ UnitTurretBrain     塔 AI（索敌→原地开火）
```

- `Unit.Awake`：初始化血量、把 `UnitDefinition` 写进 `StatBlock`、调用各能力的 `Initialize(this)`。
- `Unit.Update`：每帧给能力 `Tick(deltaTime)`（当前只有冷却计时）。
- `Unit.ActivateAbilities(target)`：`abilitiesEnabled` 开关 + 对每个能力做 `CanActivate` / `Execute`，塔的“关闭攻击”就是把它设为 false。
- `Unit.GetAttackRange()`：所有能力有效射程的最大值（`AttackAbility` 为射程 + hitPadding 0.6）。

## 三、关键实现

### 3.1 数据与属性

- `UnitDefinition`（`Assets/UnitData/*.asset`）：displayName / team / maxHealth / attack / moveSpeed / attackInterval / range / splashRadius / canMove / canAttack。
- 运行时数值统一走 `StatBlock`，`StatType`：MaxHealth、Attack、MoveSpeed、AttackInterval、Range、SplashRadius。后续加 buff 只改这个容器，不用碰单位脚本。
- 当前数值：敌人 100 血 / 10 攻 / 2 速 / 2s 间隔 / 1.5 射程；箭塔 500 血 / 5 攻 / 1s 间隔 / 20 射程。

### 3.2 血量与索敌

- `UnitHealth`：`TakeDamage` → 事件 → `destroyOnDeath`（0.3s 延迟销毁）；`logDamage` 输出每一跳伤害与死亡日志。
- `DistanceTo` 用碰撞体包围盒的最近点计算（非凸 MeshCollider 的 `ClosestPoint` 不可靠，统一用 bounds 近似）。
- `UnitRegistry`：静态注册表，`FindNearestHostile(position, team, range)` 做线性搜索；单位规模上来后需要换空间分区。

### 3.3 能力

- `UnitAbility`：`Initialize(owner)` / `Tick` / `CanActivate` / `Execute` / `EffectiveRange`。
- `AttackAbility`：冷却 = 攻击间隔；命中距离 = 射程 + hitPadding；可选溅射（对敌对阵营按半径二次判定）。
- 新增能力（治疗、光环、冲锋）只需继承 `UnitAbility` 挂到单位上，`Unit` 自动调度。

### 3.4 贴地移动（UnitMover）

路点只提供水平走向，高度完全由脚下探测决定：

1. 脚底位置 = `transform.position - up * groundOffset`（敌人 groundOffset = 1，即胶囊半高）。
2. 每帧先对当前位置探测一次，再对候选位置（朝当前路点前进 `speed * dt`）探测一次。
3. 探测：从脚底上方 2m 向下 `SphereCast`（半径 0.35），只接受：
   - 坡度 ≤ `maxSlopeAngle`（45°）；
   - 落点高度在 `[脚底 - snapDistance(0.5), 脚底 + stepHeight(0.3)]` 区间内；
   - 不是自己子物体的碰撞体。
   取其中最高的表面。
4. 找不到合法表面（陡坡、悬空、落差过大）→ 原地不动。
5. 朝向用 `RotateTowards`（540°/s）转向移动方向；到达路点 0.25m 内切下一个点。

参数（`UnitMover` 序列化字段）：`route`、`arriveThreshold`、`groundMask`、`sphereRadius`、`groundOffset`、`maxSlopeAngle`、`stepHeight`、`snapDistance`、`turnSpeed`。

**踩坑**：球体起点必须离脚底足够远（当前 2m）。起点若与斜坡重叠，Unity 的 `SphereCast` 会直接忽略该碰撞体，探测落到下层路面，表现为“贴不住坡、从坡下面穿过去”。

### 3.5 AI

- `EnemyBrain`：0.25s 搜索间隔，`acquireRange` 7m 内找最近敌对单位；目标在有效射程内就 `mover.SetPaused(true)` 并开火；目标死亡（或销毁）后清空目标、恢复移动，下一轮搜索自动转火。
- `UnitTurretBrain`：不需要移动，索敌后原地攻击，攻击开关由 `Unit.abilitiesEnabled` 控制。

## 六、已知限制与下一步

1. **折线硬拐角**：`UnitMover` 直奔当前路点，转向只是追随移动方向。建议把路点转成 centripetal Catmull-Rom 曲线（弧长参数化 + 朝切线转向），约 40 行；急弯处需限制圆角半径（0.5~0.8m），否则会切坡沿/塔体。备选方案是前视 steering（实现更短，但切角更多）。
2. **攻击时不朝向目标**：进入射程即 `SetPaused(true)`，`Update` 提前返回，朝向冻结。可在暂停时平滑转向目标。
3. **无动态重规划**：路线固定，转火只影响“何时停下”，不会改路线；沿路网寻路需要桥接层：
   - 现成接口：`TDRoadNetwork.TryGetNodePath`（BFS）、`GetEndpointNodeIds`、`FindNearestNode`、`TDRoadMeshBuilder.BuildEdgeSpline`（与路面同一条贝塞尔中心线，支持圆角）；
   - 缺：起终点选择 → 逐边按 1~2m 采样 → 生成 `UnitRoute` 的运行时组件；从当前位置投影到最近节点/边再 BFS 的重规划；`EnemyBrain` 目标切换时调用；
   - 注意：`TDRoadNetwork` 目前只在 `RoadWorkflow_Test.unity`，MVP 的旧 PolyShape 路没有图数据，需要先“从旧路导入”再微调。
4. **停步余量仅 4cm**（2.06 vs 2.1）：调整塔碰撞体或射程时容易从“能打到”变成“够不到”。
5. **索敌是 O(N) 线性搜索**：单位数量上千时需要网格/四叉树。
6. 敌人/塔放在 Ignore Raycast 层，探测靠这个层排除自身与其他单位碰撞体；新增单位层时要同步维护 `groundMask`。
