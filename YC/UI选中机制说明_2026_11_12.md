# UI 选中机制说明（2026-11-12）

本文描述 `Assets/Script/UI/` 这套单位选择与部队预览面板的实现约定，供协作时快速上手。
设计依据：[YXZ/交互式设计案/单位选择与部队预览UI面板.doc](../YXZ/交互式设计案/单位选择与部队预览UI面板.doc)。

## 一句话概括

鼠标输入（`SelectionInputReader`）只负责翻译“单击 / 拖框 / 取消”三种意图，
所有选择状态只保存在 `SelectionService` 一处；选择集合变化时通过事件同时驱动
场景描边（`SelectionHighlighter`）和面板卡片（`RosterPanelView`）。

## 1. 选择状态的唯一真相源

`SelectionService`（`Assets/Script/UI/Interaction/SelectionService.cs`）持有
`List<ISelectable> selected`，是“当前选中了谁”的唯一来源。

- 全局入口：`SelectionService.Instance`。
- 只读访问：`Selected` / `Count`。
- 变更事件：`SelectionChanged`，参数是变更后的只读集合。
- 任何系统（面板、指令系统、调试面板）都应订阅事件或每次重读 `Selected`，
  **不要自己缓存一份选择列表** —— 单位会死亡销毁，缓存会留悬空引用。

`SetSelection()` 是唯一写入口：

1. 先过滤 `null`、`!IsSelectable` 的对象并去重；
2. 若新旧集合完全相同（`SameSet`），直接返回，不触发事件；
3. 否则先 `SelectionHighlighter.ApplyDiff(旧, 新)` 更新表现，再触发 `SelectionChanged`。

## 2. 输入如何变成选择

`SelectionInputReader`（同一物体上，`Update` 中读 Input System 鼠标状态）：

| 操作 | 判定 | 结果 |
|---|---|---|
| 左键按下 | 指针不在 UI 上 | 开始一次可能的拖拽，显示框选矩形 |
| 拖动 ≥ `dragThresholdPixels`（默认 6px） | 松开时 | 走框选 `HandleDragSelect` |
| 拖动 < 6px | 松开时 | 走单击 `HandleClick` |
| 右键 / Esc | 开启 `enableCancelInput` 时 | `Clear()` 清空选择 |

**指针在 UI 上时整次操作都不进入场景选择**（按下和松开都检查
`EventSystem.IsPointerOverGameObject`），避免点面板按钮时误清空选择。

### 单击规则（`HandleClick`）

- `PickAt` 在候选单位中取“屏幕距离最近且在命中半径内”的一个。
- 命中半径 = `max(单位投影后的像素半径, 0.02 × 屏幕高度)`，
  小单位也容易点中，且不随分辨率变化而变难。
- **不按 Ctrl**：点中单位 = 替换当前选择（先全部取消再选中它）；
  点空白 = 清空选择。符合“再次点击其他区域会取消上次选择”。
- **按住 Ctrl**：点中单位 = 切换该单位（已选则移出，未选则加入）；
  点空白 = 什么都不做。

### 框选规则（`HandleDragSelect`）

- 矩形由 `ScreenProjector.RectFromPoints` 构造，四个拖拽方向都得到正尺寸矩形。
- 命中判定默认是 **圆与矩形相交**（搭边即算）；`SelectionService.requireFullContainment`
  勾选后改为“单位包围球必须完全落在矩形内”。
- 矩形面积退化（原地点击）时按取消处理。
- **不按 Ctrl**：用矩形内的单位替换选择；框内为空 = 清空。
- **按住 Ctrl**：把矩形内单位并入现有选择。

## 3. 单位如何变成“可选”

`ISelectable` 是交互层唯一依赖的接口，当前实现是 `UnitSelectable`，
它挂在 `UnitHealth` 所在物体上，是单位系统与 UI 系统之间唯一的连接点。

- `IsSelectable = health != null && health.IsAlive && isActiveAndEnabled`。
- `Team` 取阵营时优先读 `Unit.Definition.team`（权威模板值），
  其次回退 `UnitHealth.team`。这样能绕开 `Unit.Awake` 用模板覆盖前的时序窗口，
  否则面板会把战士/塔误判成 Enemy。
- `WorldRadius`：优先使用 Inspector 覆盖值，否则取子碰撞体包围盒的最大半径，
  最后退化为 0.5。
- `DisplayName`：优先 `UnitDefinition.displayName`，否则物体名。

单位获取组件的两条路径：

1. **场景预摆单位**：由编辑器工具 `Tools/UI/Create Selection Test Scene`
   在生成 `Assets/Scenes/UI_Test.unity` 时挂好。
2. **运行时刷出的怪**：`UnitSelectableBootstrap` 订阅 `UnitRegistry.Changed`，
   单位注册进注册表时自动补挂 `UnitSelectable`。**不修改预制体资产**，
   同一份预制体在别的场景不受影响。

`UnitRegistry.Changed` 由 `UnitHealth.OnEnable/OnDisable` 的注册/注销触发，
面板也订阅它来做到“生成/死亡时及时刷新”，而不是每帧轮询。

## 4. 屏幕投影与命中算法

`ScreenProjector`（`Assets/Script/UI/Logic/`，纯静态、无项目依赖，可单测）：

- `TryProjectCircle` 把世界位置 + 世界半径投影为屏幕圆心 + 像素半径。
  正交相机按 `pixelHeight / (orthographicSize × 2)` 换算；透视相机按该点视距换算。
- 位于相机后方（`z <= 0`）的单位直接跳过，不会被误选。
- `IsCircleOverlappingRect` / `IsCircleInsideRect` 分别对应宽松/严格框选判定。

## 5. 选中高亮

`SelectionHighlighter` 的核心约束：**绝不修改单位本体材质**。
单位材质是多个实例共用的 `.mat`，替换 shader 很难与 URP Lit 像素级一致（实测会变暗）。

选中时的做法：

1. 对单位下每个 `Renderer`，把共享描边材质
   （`Assets/Resources/UIHighlight/SelectionOutline.shader`，inverted hull）
   **追加**到材质数组末尾；
2. 原始材质数组保存到该渲染器物体上的 `SelectionOutlineState`；
3. 颜色/宽度通过 `MaterialPropertyBlock` 设置（友军青蓝、敌军橙红、中立灰白），
   不产生材质实例。

取消选中时把材质数组原样还原并销毁 `SelectionOutlineState`，
单位立即回到原 shader / 原亮度。`SelectionOutlineState` 挂在渲染器物体上，
单位销毁时随之回收，不会出现静态字典式的悬空缓存。

## 6. 面板如何联动

`RosterPanelView` 不自己维护单位清单：

- 刷新时调用 `SelectionService.GatherCandidates()`（从 `UnitRegistry.All` 现取，
  过滤死亡/不可选），交给 `RosterModel` 按 `Team` 分成敌人/友军两栏并稳定排序
  （先显示名，再实例 ID 兜底）。
- 每栏 3 列 × 2 行 = 6 张卡片，超出时显示 `+X` 角标；点角标打开完整列表。
- 数据来源事件：`UnitRegistry.Changed` → 帧末刷新；`SelectionChanged` → 同步卡片选中态。
- 反向联动：点卡片调用 `selection.Select(card, false)`（不累加，替换选择），
  场景框选/单击的结果又通过 `SelectionChanged` 同步到卡片描边。
- 面板通过挡在场景前的 uGUI 元素接收点击，`SelectionInputReader` 检测到指针在 UI 上
  就不会把这次点击当成场景选择。

## 7. 生命周期与已知边界

- 选中集合里的引用在单位死亡后不保证立即移除；使用方必须重新检查 `IsSelectable`，
  不要凭旧引用操作单位。面板每次重建都从注册表现取，因此卡片本身不会残留。
- `GatherCandidates` 每帧现收集，不做静态缓存 —— 单位持续生成/销毁，缓存需要额外失效维护。
- 中立单位不进入面板（设计案只定义敌人/友军两栏），但仍可被场景单击选中。
- 完整列表未做虚拟化，当前几十个单位的规模够用；规模再大需要换 `ScrollRect` + 对象池。
