NavMesh AI 验收（2026-10-29）

测试场景：Assets/Scenes/RoadWorkflow_Test.unity（有已烘焙 NavMesh）
- 两处坡顶各 2 名战士 + 1 座塔（塔攻击保持关闭，投射物留待后续）
- 路网西端 node6 由 UnitSpawner 生成 30 名普通敌人，巡逻终点 (15.89, 0.02, -2.39)
- 菜单 `Tools/Unit/Create AI Test Scene` 一键生成/重建（可重复执行，先删同名对象）

实现内容
- 移动：新增 `UnitLocomotion` 抽象与 `UnitMotor`（NavMeshAgent；速度每帧取 StatBlock.MoveSpeed，攻击时 isStopped，目标死亡后恢复）；`UnitMover` 也实现该抽象，MVP 旧场景继续可用。`EnemyBrain` 不再硬依赖 `UnitMover`。
- 战士：`WarriorBrain` 状态 Idle → Chase → Attack → Return；检测 10m、拴绳 14m。
- 拦截：`UnitEvents.InterceptRequested` + `InterceptRequest`。战士锁定敌人时发出请求；`EnemyBrain` 检查目标是自己、双方存活、阵营敌对、拦截者距离 ≤ 12m、未被其他拦截者占用。接受后转火拦截者；拦截者死亡或距离 > 20m 时释放并重新索敌。
- 攻击延迟：`AttackAbility.damageDelay = 0.3s`。满足射程与冷却即起手并开始冷却，0.3s 后结算伤害/溅射；起手期间目标死亡则落空。
- 生成器：`UnitSpawner` 间隔 1s 生成 30 个敌人，出生点吸附 NavMesh。
- 编辑器布置：`Assets/Script/Unit/Editor/UnitAITestSetup.cs`（`UnitDemoSetup` 的 partial）。

验收结果

1. 敌人状态机 ✔
- 敌人从西端依次沿 NavMesh 走向东侧巡逻点；进入 7m 索敌半径后锁定最近单位。
- 仇恨转移日志：Enemy_Normal_Nav_4~8 先锁定 AI_Warrior_2 → 其死亡后重新锁定 AI_Warrior_3 → 再死后锁定 AI_Tower_East。
- 状态采样：35s 时 30 只存活，Attack=1、Chase=19、Patrol=10。

2. 战士状态机 ✔
- 四名战士均出现 `[Warrior] -> Idle`，敌人接近后 `-> Chase`，进入射程后 `-> Attack`。
- 定向验证：清除全部敌人并停掉生成器后，两名存活战士 `-> Return`，沿 NavMesh 回到坡顶后 `-> Idle`（位置 (-2.86,4.52,-4.18) / (-5.23,4.56,-4.16)，回到驻守点）。

3. 伤害与死亡 ✔
- 双向掉血日志：`AI_Warrior_2 受到 10.0 伤害`、`Enemy_Normal_Nav_0 受到 5.0 伤害` 等。
- 死亡事件：`AI_Warrior_0/1/2/3 已死亡`、`AI_Tower_East 已死亡`，后续从注册表注销，无残留引用（修复后 0 error）。
- 伤害延迟实测（日志 t 为 Time.time）：
  - 起手 t=5.00 → 命中 t=5.29
  - 起手 t=7.02 → 命中 t=7.31
  - 起手 t=11.43 → 命中 t=11.73
  起手到命中约 0.30s，符合帧级容差。

4. 拦截事件 ✔
- `[Intercept] AI_Warrior_2 请求拦截 Enemy_Normal_Nav_0` → `[Intercept] Enemy_Normal_Nav_0 接受 AI_Warrior_2 的拦截，改为攻击 AI_Warrior_2`
- 拦截者死亡后：`[Intercept] Enemy_Normal_Nav_0 解除对 AI_Warrior_2 的拦截`，随后敌人重新索敌。

发现并修复的问题
- 假空判断写反：`unityObject != null && unityObject == null` 对已销毁的 UnityEngine.Object 永远不成立，导致销毁后的 UnitHealth 仍被视为存活。表现为战士目标被销毁后卡在 Attack，并持续抛 MissingReferenceException。
- 修复为 `unityObject == null`；涉及 `EnemyBrain`、`WarriorBrain`、`AttackAbility`、`UnitTurretBrain`。修复后清除敌人，战士正常 Return → Idle，控制台 0 error。
