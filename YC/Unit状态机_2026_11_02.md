# 单位状态机（2026-11-02 修订）

> 本文记录用户确认的敌人/友军状态机，并对照当前实现做符合度核查。
> 实现文件：`Assets/Script/Unit/EnemyBrain.cs`、`Assets/Script/Unit/WarriorBrain.cs`。

## 敌人

```
Idle
 └─ 是否被拦截
     ├─ 是 → 拦截我的人是否在我的攻击范围内
     │       ├─ 是 → 攻击
     │       └─ 否 → Idle
     └─ 否 → 判断攻击范围内是否有敌对单位
             ├─ 是 → 攻击
             └─ 否 → 判断感知范围内是否有敌对单位
                     ├─ 是 → 移动到目标位置 → 判断攻击范围内是否有敌对单位
                     └─ 否 → Idle

攻击 ── 单位丢失 → Idle
任何状态 ── 生命值为 0 → 死亡
```

要点：**被拦截时，拦截者不在攻击范围内就原地待命（Idle），不能继续朝拦截者移动。**

## 友军

```
Idle
 └─ 是否有拦截单位
     ├─ 是 → 拦截单位是否在攻击范围内
     │       ├─ 是 → 攻击
     │       └─ 否 → 移动到目标位置 → 拦截单位是否在攻击范围内
     └─ 否 → 判断攻击范围内是否有敌对单位
             ├─ 是 → 把目标确定为指定拦截单位 → Idle
             └─ 否 → 判断感知范围内是否有敌对单位
                     ├─ 是 → 把目标确定为指定拦截单位 → Idle
                     └─ 否 → Idle

攻击 ── 单位丢失 → Idle
任何状态 ── 生命值为 0 → 死亡
```

## 现状符合度核查

| 状态机要求 | 当前实现 | 结论 |
|---|---|---|
| 敌人：被拦截 + 拦截者在攻击范围内 → 攻击 | `EnemyBrain.Update` → `interceptedBy != null` 时 `CheckAttack()`，命中则 `Attack` + `SetPaused(true)` + `ActivateAbilities` | 符合（保持不变） |
| 敌人：被拦截 + 拦截者不在攻击范围 → Idle（停住） | 修复前：`Chase()` 追向拦截者，只有进入射程才停 | **不符合 → 已修复**：新增 `Hold()`，进入 `Idle` 并 `Halt()`（`Stop()` + `SetPaused(true)`） |
| 敌人：解除拦截（拦截者死亡 / 超出 20m / 拦截者主动放弃追击）后恢复索敌 | `ValidateIntercept()` 清空 `interceptedBy`/`target`；`UnitEvents.InterceptReleased` 让战士在拴绳放弃目标时通知敌人立即解除 | 符合 |
| 敌人：未被拦截时按攻击范围 → 感知范围 → 移动 → 攻击 | `CheckAttack()` → `Chase()`（`acquireRange` 即感知范围） | 符合 |
| 敌人：感知范围无敌对单位 → Idle | 无目标时 `Patrol()`：有巡逻点且未到达则 `Patrol`（坐标移动），到达则 `Halt()`（真静止）；无巡逻点则 `Stop()` + `SetPaused(false)`，把移动交还给路线跟随 | 有意偏离（保留朝终点移动的巡逻扩展，见下） |
| 敌人：攻击目标丢失 → Idle | 目标丢失当帧 `Hold()`（`Idle` + `Halt()`）；下一帧从 Idle 进入新一轮判定，仍无目标则朝终点（巡逻点）移动。目标死亡、拦截者死亡、`InterceptReleased`、20m 超距解除均走同一路径 | 符合（Idle 不是终点，下一轮判定从 Idle 继续） |
| 任何状态：生命值为 0 → 死亡 | `OnSelfDied` 禁用 Brain 并 `locomotion.Halt()`（`Stop()` + 暂停，销毁延迟期间不再移动） | 符合 |
| 友军：有拦截单位且在射程 → 攻击；不在 → 追 | `WarriorBrain.Update`：有 `target` 时 `CheckAttack()` 否则 `Chase()`；`AcquireTarget()` 先判拴绳再向敌人发 `InterceptRequested`。接战距离取双方射程较小值，避免停在敌人够不到的位置 | 符合 |
| 友军：无拦截单位 → 攻击范围内有敌人则设为拦截目标并 Idle；否则看感知范围 | `AcquireTarget()` 用 `detectRange=10` 取最近敌对单位（攻击范围 2.6 < 10，故射程内有敌人必能被选中），选中后停在 `Attack`，否则 `Chase` | 功能等价（扫描半径不同，见下） |
| 友军：目标丢失 → Idle | 目标死亡/超拴绳 → `target=null` → `Guard()` 返回驻守点后 `Idle` | 基本符合（多了返回驻守点） |
| 任何状态：生命值为 0 → 死亡 | `OnSelfDied` 禁用 Brain 并 `locomotion.Halt()`（`Stop()` + 暂停，销毁延迟期间不再移动） | 符合 |

## 有意保留的扩展（与状态机不冲突）

1. **敌人巡逻**：`EnemyBrain` 无目标时会前往 `patrolGoal`（AI 测试场景中 30 个敌人生成后向东行进）。状态机里写的是 `Idle`，这里把「巡逻点未到达」视为导航态，到达后即 `Idle`；目标丢失当帧先回到 `Idle`，下一帧立即进入新一轮判定并继续朝终点移动。
2. **友军返回驻守点**：`WarriorBrain` 目标丢失后先 `Return` 到 `guardPosition`，再 `Idle`，而不是原地 `Idle`。
3. **友军扫描半径**：`AcquireTarget()` 以 `detectRange` 取最近敌人，选中即视为「指定拦截单位」；射程内检测已包含在 `CheckAttack()` 中。

## 移动语义：Stop 与 Halt

`UnitLocomotion.Stop()` 只是清空当前坐标目标，`UnitMover` 在下一帧会恢复路线跟随，所以 **`Stop()` 不等于停住**。需要真正静止时统一用 `UnitLocomotion.Halt()`（`Stop()` + `SetPaused(true)`）：

| 场景 | 调用 | 结果 |
|---|---|---|
| 被拦截但拦截者不在射程（`EnemyBrain.Hold`） | `Halt()` | 原地不动 |
| 目标丢失当帧、超距解除当帧（`Hold` 后再判定） | `Halt()` | 原地不动一帧，下一帧再进入判定 |
| 到达 AI 巡逻终点（`EnemyBrain.Patrol`） | `Halt()` | 真正停下 |
| 战士到达驻守点（`WarriorBrain.Guard`） | `Halt()` | 真正停下 |
| 敌人/战士死亡（`OnSelfDied`） | `Halt()` | 销毁延迟期间不再移动，也不会退回路线 |
| 无 AI 巡逻点（演示敌人，移动靠路线） | `Stop()` + `SetPaused(false)` | 退出坐标模式，移动交还给路线跟随 |
| 追击 / 前往终点 / 返回驻守点 | `MoveTo()`（内部会解除暂停） | 坐标移动 |

无巡逻点的敌人处于 `Idle` 时仍会沿路线前进——这是 `UnitMover` 演示敌人的预期行为，并非「Idle 还在乱跑」。被拦截时 `Halt()` 会暂停路线，解除拦截后从 Idle 恢复路线跟随。

## 射程与解除的边界处理

- 敌人射程 1.5 + 命中容差 0.6 = 2.1，战士 2.0 + 0.6 = 2.6。若战士只按自身射程停步，会在中心距约 3.0m 停下，而被拦截的敌人需要 2.5m 才能还手，形成单方面挨打。`WarriorBrain.EngagedAttackRange()` 改为取双方射程较小者，战士会多靠近约 0.5m，敌人进入自己射程后即转入 Attack。
- 战士因超出拴绳放弃目标时发出 `UnitEvents.InterceptReleased`，敌人立即解除拦截并恢复索敌，避免「战士已回驻守点、敌人仍原地待命」的僵局。拦截者死亡仍由 `ValidateIntercept()` 兜底。
- 敌人被拦截且拦截者不在射程内时严格保持 Idle（不向拦截者移动），靠近的动作由拦截者一侧完成。
- `WarriorBrain.AcquireTarget()` 先判拴绳（`DistanceToGuard > leashRange` 直接返回）再发拦截请求，避免「请求 → 下一帧因超绳释放 → 再请求」的抖动。拦截行为由 `Assets/Tests/EditMode/InterceptStateTests.cs` 覆盖：被拦截超射程保持 Idle、射程内攻击、移动中被拦截即停、目标丢失当帧回 Idle 且下一帧朝终点移动、`InterceptReleased` 后先 Idle 再重新判定、20m 超距解除、超拴绳不发请求、敌人/战士死亡时 Brain 禁用并停止移动（含巡逻移动中死亡）、到达巡逻终点后真正停下、无巡逻点敌人在 Idle 期间把移动交还路线并在拦截解除后恢复。
- `AttackAbility.ApplyHit` 结算起手伤害前同时检查 Owner 存活，死亡单位不会再打出已起手的伤害。
