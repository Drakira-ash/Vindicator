# 0003 — 以启动时对账为基线，不伪装常驻监控

- 日期：2026-10-28
- 状态：接受
- 影响组件：会话生命周期、watch、Git hooks

## 背景

要求跨会话感知项目变化，但不能虚构后台能力。环境没有已安装并验证的调度器/守护进程；Unity 编辑器连接也未确认。Git hooks 只影响本机，不随仓库分发。

## 决定

- **基线**：每次会话开始运行 `session-start`，比较工作树内容签名与索引 manifest，必要时重建索引，并执行校验、同步 Git 状态、显示任务与下一步。
- **可选实时感知**：
  - 前台 `watch`：轮询 mtime/size 签名，防抖后标记 stale；可选自动重建。通过心跳文件报告“运行中/已停止”。
  - `hooks install`：显式安装 `post-commit` / `post-checkout`，仅追加事件并标记 stale；不覆盖非 managed 的已有 hook；默认不安装。
- **明确限制**：没有 OS 级守护进程、没有 Unity 回调；空闲时不会自动发现变化。文档与 `status` 必须如实显示“未启动/心跳过期”。

## 替代方案

1. Windows 任务计划/服务：可常驻，但需要安装系统级任务，未经用户授权，且跨机器不可移植。
2. Unity Editor 回调：可实时感知导入/保存，但依赖编辑器改写代码，且只覆盖 Unity 进程运行期间。
3. MCP 事件流：依赖连接与工具支持，当前未验证。

## 后果

- 空闲期间的变化只在下次 `session-start`/`validate`/`status` 时被发现，这是已知且显式的限制。
- 不会出现“以为有监控、实际没有”的假象；状态可验证。
- 若用户需要常驻，可先启用 `watch` 或 hooks，再评估任务计划；届时重审本决策。
