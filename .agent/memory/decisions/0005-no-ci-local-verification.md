# 0005 — 不接 CI；验证只在本地编辑器内完成

- 日期：2026-10-28
- 状态：接受
- 影响组件：验证范围、backlog、文档与记忆中的能力描述

## 背景

项目是两人协作的小型 Unity 工程，当前没有测试资产，也没有需要外部合入方的流水线。用户明确决定：不接 CI（GitHub Actions/GameCI/云端构建），本地只需要“编辑器内一键跑测试”。

## 决定

- **不接任何 CI**：仓库不增加 workflow，不为 CI 做许可证/镜像/缓存适配。
- **本地验证为唯一验收路径**：
  - 编译：编辑器菜单 `Tools/Harness/Verify Compilation` + `agent.py unity-verify --adopt-editor`。
  - 测试：编辑器内一键运行 EditMode 测试，结果写入本机证据文件；不需要关闭编辑器。
  - 批处理编译 `agent.py unity-verify` 保留为“编辑器关闭时的补充手段”，不再以 CI/无人值守为理由扩展它。
- **文档与记忆不出现 CI 作为待办或能力缺口**；只在决策记录中说明“明确不做”。

## 替代方案

1. GitHub Actions + GameCI：技术可行，但需要许可证激活、私有仓库分钟数消耗、冷导入慢；本项目没有合入方，收益不足。
2. self-hosted runner：无需激活，但要求本机常开；日常单人开发不如直接用编辑器。
3. 只做批处理：与“本地编辑器内一键验证”的目标相悖。

## 后果

- 验证结果只对本机有意义；换机器/新克隆需重新跑。
- 没有“推送即验证”的自动把关；依赖开发者在提交前主动运行。
- 若未来出现外部协作者或需要 PR 门禁，重审本决策；届时再评估许可证与成本。
