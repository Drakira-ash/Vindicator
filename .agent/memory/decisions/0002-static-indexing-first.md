# 0002 — 先做静态索引与校验，不依赖 Unity 运行

- 日期：2026-10-28
- 状态：接受
- 影响组件：`agent.py` 索引/校验

## 背景

需要在不启动 Unity、不占用项目锁的情况下，跨会话恢复项目结构、资产关系与代码地图。本会话没有可用的 Unity MCP 工具；批处理编译尚未验证。项目规模较小（约 164 个源文件、51 个资产），静态解析成本低。

## 决定

- 用 Python 直接读取文件系统、`.meta`、Unity YAML 与 C# 源文件，生成 `files.json`、`assets.json`、`code-map.json`、`dependencies.json`。
- 代码地图明确标注为**启发式正则解析**，不声称等价于编译器。
- 包内脚本 GUID 通过 `Library/PackageCache/**/*.meta` 解析，并以 `packages-lock.json` 哈希做本地缓存；无缓存时降级为 `skip`，不误报。
- Unity 批处理编译/自动化测试留作 backlog（`harness-unity-verify`），不在 bootstrap 中运行。

## 替代方案

1. Unity `-batchmode -quit` 导入/编译：能发现编译错误，但慢、占锁、需要编辑器入口方法；本次未获授权测试。
2. Unity MCP：可查询场景/资产，但依赖编辑器连接，本会话不可用；且不适合作为离线基线。
3. Roslyn/语言服务器：更准确的代码地图，但引入依赖与构建步骤，超出当前需要。

## 后果

- Harness 可在新鲜克隆、无 `Library/`、无编辑器时工作。
- 无法发现编译错误、序列化错误、运行时引用问题；这些仍需 Unity/人工验收。
- 正则解析可能漏掉嵌套/泛型/条件编译；结果只作导航与提醒，不作删除依据。
- 若启用批处理编译或 MCP，应新增检查而不是替换静态索引。
