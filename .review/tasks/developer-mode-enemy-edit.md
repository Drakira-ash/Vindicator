# 任务基线：开发者模式敌人可选/可销毁，生成敌人会前进

- 任务 id：`developer-mode-enemy-edit`
- 来源：用户反馈（2026-11-15）
  - 敌人不能选取和销毁；
  - 敌人不能被控制，但至少要做到能够编辑；
  - 新增的敌人会在原地不动，应该和原本的敌人一样朝目标前进。
- 关联：`新计划.txt` 开发者模式条目、`.review/tasks/developer-unit-spawn.md`

## 需求

用户反馈：敌人在开发者模式下不能选取和销毁；敌人不能被玩家控制，但至少要做到能够编辑；新生成的敌人原地不动，应该和原本的敌人一样朝目标前进。

## 验收标准

- A1 开发者模式下，点选与框选都能选中敌方单位（任意存活单位）。
  > 原话：“敌人不能选取和销毁。”
- A2 开发者模式下按 `K`（或面板“销毁选中”）能销毁选中的敌人，选择随之清空。
  > 原话：“敌人不能选取和销毁。”
- A3 关闭开发者模式后，选择恢复原行为：仅存活、Player 阵营、带 `WarriorBrain` 的单位。
  > 原话：“但至少要做到能够编辑。”
- A4 面板逐行“销毁”对任意单位继续有效（原有行为不得回退）。
  > 原话：“敌人不能选取和销毁。”
- B1 开发者模式下即使选中敌人，右键移动/攻击命令也不会下发到敌人（不为其添加 `UnitCommander` 命令）。
  > 原话：“敌人不能被控制。但至少要做到能够编辑。”
- B2 敌人不会被编入玩家小队（`CreateSquadFromSelection` 忽略敌人）。
  > 原话：“敌人不能被控制。但至少要做到能够编辑。”
- B3 选中玩家单位 + 敌人混编时，命令只作用于玩家单位。
  > 原话：“敌人不能被控制。但至少要做到能够编辑。”
- C1 场景存在 `UnitSpawner` 且配置了 `patrolGoal` 时，`S`/`D`/面板生成的敌人在实例化后继承该巡逻目标。
  > 原话：“新增的敌人会在原地不动，应该和原本的敌人一样会朝着目标前进。”
- C2 场景没有 spawner 时，退化为复用场景已有 `EnemyBrain` 的巡逻目标。
  > 原话：“新增的敌人会在原地不动，应该和原本的敌人一样会朝着目标前进。”
- C3 两者都没有时保持可生成，不抛异常（原地待命，与预制体默认一致）。
  > 原话：“新增的敌人会在原地不动。”
- C4 新敌人与原本敌人行为一致：无索敌目标时朝巡逻目标移动，发现敌对目标后追击。
  > 原话：“应该和原本的敌人一样会朝着目标前进。”
- D1 EditMode 覆盖：开发者模式下敌人可选、K 可销毁选中敌人、命令过滤、生成敌人获得巡逻目标。
- D2 Unity 编译 0 error / 0 warning；EditMode 全通过；`harness validate` 通过。
